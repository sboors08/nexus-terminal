# NEXUS Setup Engine Multi-Timeframe Runtime v0.1

## Для чего нужен этап

Scanner должен показывать реальные независимые сетапы каждого доступного таймфрейма, а не декоративные пункты фильтра. Этот контракт подключает production Setup Engine к `1m`, `5m`, `15m`, `1h` и `4h`.

## Что изменено

- сохранён единый realtime-поток Binance `1m`;
- закрытые `1m` свечи детерминированно агрегируются в `5m`, `15m`, `1h` и `4h`;
- для каждого таймфрейма запускается отдельный `SetupDetectionPipeline`;
- Level Line, candidate id, episode id и история остаются разделены по таймфрейму;
- stage evaluation читает последнюю закрытую свечу таймфрейма самого кандидата;
- открытая текущая агрегированная свеча доступна для realtime, но игнорируется Level Lines detector до закрытия.
- Scanner всегда показывает пять production TF в фильтре; отсутствие текущего кандидата на выбранном TF отображается как пустой результат, а не скрывает сам TF.

## Production timeframes

1. `1m` — исходные закрытые минутные свечи.
2. `5m` — пять выровненных минутных свечей.
3. `15m` — пятнадцать выровненных минутных свечей.
4. `1h` — шестьдесят выровненных минутных свечей.
5. `4h` — двести сорок выровненных минутных свечей.

## Инварианты безопасности

- пороги Level Lines не изменены;
- пороги Approach и Confirmation не изменены;
- логика направления и типа сетапа не изменена;
- таймфреймы не объединяются между собой;
- торговые ордера и сигналы не создаются;
- future candles не используются;
- существующий `1m` контракт остаётся совместимым.
